## 1. 项目概述

### 1.1 一句话定位
为合规研究人员提供**可溯源的全球AI法规知识图谱查询平台**，支持按司法管辖区、主题、时间线快速检索和关系追溯。

### 1.2 目标用户
- **主要用户**：Capco 合规研究员（如 Alan）
- **潜在用户**：金融服务客户的合规团队、政策分析师

### 1.3 核心价值
1. **快速定位法规**：从1,174+条全球AI法规中，按国家/类型/主题秒级检索
2. **可信溯源**：每条法规链接到regulations.ai记录页和官方政府源，满足合规审计要求
3. **关系洞察**：通过图谱展示法规间修订、实施、引用关系，以及司法管辖区分布
4. **时间线掌控**：法规日历展示213个即将生效的里程碑事件（2026-2045）

### 1.4 成功标准（可量化）
| 指标 | 目标值 |
|------|--------|
| 法规搜索响应时间 | < 2秒 |
| 图谱可视化渲染时间 | < 3秒（30节点），< 10秒（300节点） |
| 官方来源链接可用性 | ≥ 95%（排除已知缺失如`RAI-AR-NA-PJUAIXX-2024`） |
| 用户能在5分钟内找到目标法规 | ≥ 90%任务成功率（待用户测试验证） |

## 3. 核心业务流程

### 流程1：按条件检索法规
1. **研究员** 打开应用首页 → 看到法规列表（30条，带分页）
2. **研究员** 在搜索框输入关键词（如"EU AI Act"）或选择过滤器（司法管辖区="European Union"，类型="Regulation"，状态="In Force"） → 点击"搜索"
3. **系统** 向FastAPI发送查询请求 → **后端** 查询Neo4j（Cypher模板） → 返回匹配的Regulation节点（包含instrument_id、name、jurisdiction、type、legal_force）
4. **前端** 在表格中展示结果，每行显示：法规名称、司法管辖区、类型、生效日期、状态、"查看详情"按钮
5. **结果**：研究员在2秒内看到结果列表

### 流程2：查看法规详情与官方来源
1. **研究员** 在列表中点击某条法规的"查看详情" → 跳转到详情页
2. **系统** 通过instrument_id查询Neo4j → 返回Regulation节点的所有属性 + 关联的Source/Milestone/Topic节点
3. **前端** 展示：
   - 法规基本信息（名称、描述、类型、生效日期、法律效力）
   - **官方来源链接**（SOURCED_FROM/HAS_OFFICIAL_TEXT/PUBLISHED_AT，带域名标签如eur-lex.europa.eu）
   - **regulations.ai记录页链接**（record_url）
   - 实施时间线（Milestone列表，按日期排序）
   - 主题标签（Topic节点，可点击跳转到该主题的所有法规）
4. **研究员** 点击"eur-lex.europa.eu"链接 → **浏览器** 在新标签页打开官方文本
5. **结果**：研究员验证法规原文，满足审计溯源要求

### 流程3：查看法规日历
1. **研究员** 点击导航栏"法规日历" → 进入日历页面
2. **系统** 查询所有Milestone节点（按date排序，过滤未来12个月） → 返回213个事件
3. **前端** 展示日历视图：
   - 时间轴模式（按月分组）
   - 每个事件显示：日期、里程碑名称、关联法规、司法管辖区、官方来源链接
   - 支持过滤：按司法管辖区、日期范围
4. **结果**：研究员快速识别即将生效的合规义务（如"2027-12-02 EU AI Act高风险系统义务生效"）

### 流程4：图谱可视化
1. **研究员** 点击"知识图谱" → 进入图谱页面
2. **系统** 查询Neo4j（初始加载30个Regulation节点 + 关联的Jurisdiction/Topic/Source） → 返回节点和关系JSON
3. **前端** 使用d3.js渲染力导向图：
   - **节点**：Regulation（蓝色圆）、Jurisdiction（绿色方）、Topic（橙色菱形）
   - **边**：IN_JURISDICTION、HAS_TOPIC、SOURCED_FROM（不同颜色/粗细）
4. **研究员** 鼠标悬停节点 → 显示tooltip（法规名称、类型）；点击节点 → 跳转到详情页
5. **研究员** 选择过滤器（如"只显示EU法规"） → 图谱重新渲染子集
6. **结果**：研究员直观看到"European Union有哪些法规"、"governance_oversight主题关联了哪些国家"

### 4.2 本期不包含（Out of Scope）

| 功能 | 不做的理由 | 是否后续版本 |
|------|-----------|-------------|
| **用户登录/权限管理** | MVP单用户模式，无需认证 | Phase 2+（多用户） |
| **法规全文RAG问答** | 需要Postgres+pgvector+文本分块，复杂度高 | Phase 3（需完整文本抓取） |
| **法规编辑/标注** | 只读应用，数据源是regulations.ai | 不计划（数据来源只读） |
| **多跳关系推理** | 需要AMENDS/SUPERSEDES关系（当前数据未包含） | Phase 4（需扩展图谱） |
| **告警订阅/邮件通知** | 需要用户管理+后台任务 | Phase 5+ |
| **批量数据刷新UI** | MVP手动运行`neo4j_loader.py`脚本 | Phase 2（管理员功能） |
| **多语言支持** | MVP仅英文界面，法规描述保留原语言 | 不计划（法规本身多语言） |
| **导出功能（CSV/PDF）** | 非核心需求，可通过浏览器打印/复制 | Phase 3+ |
| **Postgres全文搜索** | 后端暂时只查Neo4j，Postgres延后 | Phase 3 |
| **LLM生成Cypher查询** | 研究文档明确禁止（准确率77%），只用模板 | 永久不做 |

## 5. 异常场景清单

| 功能ID | 异常场景 | 期望表现 |
|--------|----------|----------|
| **F-001** | Neo4j连接失败 | 前端显示错误提示"无法连接到图数据库，请检查Neo4j服务状态"，搜索按钮禁用 |
| **F-001** | 搜索结果为空 | 显示"未找到匹配的法规，请尝试其他关键词或过滤条件" |
| **F-001** | 搜索关键词包含特殊字符（`'`/`"`/`;`） | 后端对输入进行参数化处理，防止Cypher注入 |
| **F-002** | 法规缺失官方来源URL（如`RAI-AR-NA-PJUAIXX-2024`） | 显示"官方来源：未提供"，regulations.ai记录页链接仍正常显示 |
| **F-002** | 里程碑日期格式异常（如"2024-07-18 to 2024-07-19"或包含HTML） | 后端解析日期范围，提取起始日期；若解析失败显示原始文本 |
| **F-003** | 官方来源链接404（政府网站已删除） | 点击链接时浏览器正常打开（由用户判断有效性），不做链接存活检查 |
| **F-004** | 日历事件日期为空/格式错误 | 跳过该事件，记录到控制台日志（开发者可查） |
| **F-005** | 图谱节点超过500个（全量加载导致卡顿） | 默认只加载前100个节点，提示"数据量较大，请使用过滤器缩小范围" |
| **F-006** | LLM API Key错误/API超时 | 显示错误消息"LLM API调用失败：[错误详情]"，不阻塞其他功能（LLM仅用于可选问答） |
| **F-006** | LLM API URL格式错误 | 前端校验URL格式（需http/https开头），保存前提示"请输入有效的URL" |
| **All** | 后端FastAPI崩溃/500错误 | 前端捕获网络错误，显示通用提示"服务器错误，请稍后重试"，并在控制台记录详细错误 |

## 7. 非功能性需求

### 7.1 性能
- 法规列表查询响应时间：< 2秒（30条）、< 5秒（300条）
- 图谱初始渲染：< 3秒（100节点）、< 10秒（500节点）
- 详情页加载：< 1秒
- FastAPI并发能力：支持10个并发请求不降级

### 7.2 安全
- **输入验证**：所有用户输入（搜索关键词、过滤条件）在后端进行参数化处理，防止Cypher注入
- **敏感信息保护**：LLM API Key在前端localStorage存储时使用Base64编码（注：非加密，MVP阶段警告用户"请勿在生产环境使用"），后端配置文件使用环境变量
- **官方链接校验**：不对外部链接做存活检查（避免隐私泄露和性能开销），由用户判断有效性

### 7.3 可维护性
- **代码规范**：
  - 前端：React函数组件 + TypeScript，遵循Airbnb风格
  - 后端：FastAPI + async/await，遵循PEP 8
  - 关键逻辑添加中文注释说明"为什么这样做"
- **Cypher查询**：仅使用模板化查询（20-30个预定义模板），禁止LLM生成
- **接口冻结**：一旦FastAPI与前端的JSON接口定义完成（见第8节），未经架构师批准不得修改字段名/类型

### 7.4 数据约束
- **数据来源**：所有法规数据来自regulations.ai（遵守Terms of Use §9，不允许商业再分发）
- **引用溯源**：每条法规必须包含record_url（regulations.ai记录页）+ 至少1个官方来源URL（除非原始数据缺失）
- **时间戳准确性**：Milestone的date字段若为范围（如"2024-07-18 to 2024-07-19"），取起始日期；若包含HTML标签，清洗后存储
- **图谱大小限制**：Neo4j社区版单实例，预估峰值1,500个Regulation节点 + 5,000条关系，总存储<500MB

### 7.5 兼容性
- **浏览器**：Chrome 120+、Edge 120+、Firefox 120+、Safari 17+（不支持IE）
- **分辨率**：最佳体验1920x1080，最低支持1024x768
- **Neo4j版本**：5.26-community + APOC
- **Python版本**：3.11+
- **Node.js版本**：20+ (LTS)

## 9. 术语表

| 术语 | 定义 |
|------|------|
| **RAI ID** | Regulation.AI的法规唯一标识符，格式如`RAI-EU-NA-E2AIXXX-2024` |
| **regulations.ai** | 第三方AI法规聚合平台（Smitteck GmbH运营），本应用的数据来源 |
| **官方来源** | 政府/国际组织发布的原始法规文本URL（如eur-lex.europa.eu、congress.gov） |
| **Jurisdiction** | 司法管辖区，如European Union、United States、Hong Kong |
| **InstrumentType** | 法规类型，如Regulation、Bill、Policy、Guideline |
| **Legal Force** | 法律效力状态，如InForce、PartiallyInForce、Draft、Withdrawn |
| **Milestone** | 法规实施时间线上的关键事件，如生效日期、征求意见截止日期 |
| **Topic** | 主题标签，如governance_oversight、data_protection_privacy、risk_management |
| **Cypher** | Neo4j图数据库的查询语言 |
| **d3.js** | JavaScript数据可视化库，用于渲染力导向图 |
| **shadcn** | 基于Radix UI和Tailwind CSS的React组件库 |
| **APOC** | Neo4j的扩展库（Awesome Procedures On Cypher），提供高级图算法 |
| **MVP** | Minimum Viable Product，最小可行产品 |
